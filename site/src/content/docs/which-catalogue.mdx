## How it chooses

This is the same rule `arcsec catalog recommend` uses, so the two always agree:

- The **pixel scale** is `206.265 × pixel size (µm) × binning ÷ focal length (mm)`
  arcseconds per pixel, which is how arcsec reads `XPIXSZ`, `XBINNING` and `FOCALLEN`
  from an image header.
- The **field of view** is the pixel scale times the sensor size, on each side.
  Binning does not change it.
- The catalogue is chosen for the **longer side** of the field, as
  `arcsec catalog recommend --like image.fits` does when it reads your image.
- Of the catalogues whose published field range includes that size, it suggests the
  **smallest download**. A denser catalogue also works, and can help on crowded or
  faint fields, but there is no need to download 1.2 GB when 102 MB will do.

The photometric catalogues (the V-series) add Johnson-V magnitudes and colour, for
photometry and colour calibration in software that reads ASTAP's databases. arcsec
can solve with them too, but the picker recommends a solving catalogue for that.
Installing the solving catalogue also builds arcsec's
[blind index](../catalogues/#the-blind-index) from it, which lets arcsec
[solve with no position hint](../faq/#can-it-solve-with-no-position-at-all); the
picker shows its size. For fields under 0.3° it adds `--index-min-fov 0.15` to the
install command, since the default index stops at 0.3°.

The [catalogue guide](../catalogues/) lists every catalogue, where they are installed and
how to share them with ASTAP.
